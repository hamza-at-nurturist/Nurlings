# Design

## Context

See proposal.md. The rebrand left a one-path "N" placeholder: `brand.mark` is a single path, the
source PNGs were generated by `make-placeholders.ts`, and `export-assets.ts` derives every
platform file from those PNGs. The supplied SVGs share two shapes (a blob and an orb with a
gradient); the icon adds a navy square. Bot avatars in the app are upstream's coloured shapes with
two eyes and are a separate system.

## Goals / Non-Goals

**Goals:** one set of vector sources; every icon regenerated reproducibly; no hand-edited PNGs; a
check that fails on drift.
**Non-Goals:** changing the bot avatars, the marketing site, store listing graphics, or any
internal identifier.

## Decisions

1. **SVGs are the source of truth; PNG sources are rendered from them.** `render-sources.ts`
   replaces the placeholder generator (kept `--force` and never-overwrite-by-default). Alternative,
   hand-exporting PNGs from a design tool, was rejected: it cannot be checked or reproduced.
2. **Shapes live in `brand.json`, verified against the SVGs.** The UI bundles `brand.json`, so the
   path data has to be there; a test parses the SVG files and compares, so there is still one
   authority (the files).
3. **Which art goes where.** Full mark (blob and orb): app icon, adaptive foreground, splash,
   in-app mark, desktop setup. Blob alone: favicons, Android themed icon, notification icon, where
   the orb's eyes disappear. The favicon sits on a navy rounded plate so it reads on any tab colour;
   it is drawn straight from the vector at 16, 32 and 48 pixels, not scaled down from 128.
4. **Adaptive icon safe zone.** Layers are drawn inside a 672 pixel circle (the platform's is 676),
   a margin of 2 pixels each side for anti-aliasing. The mark is wide (1.76:1), so it is still
   modest in the launcher; that is the cost of the rule.
5. **In-app colours.** The blob uses `currentColor` so it is dark on light themes and white on
   dark; a white blob on the app's light background would vanish. The wordmark puts the mark on the
   navy plate in brand white, which is the icon as drawn.
6. **Apple Icon Composer bundle.** The single layer is the full opaque app icon, so the bundle
   needs no fill of its own and no colour string had to be invented.
7. **Desktop setup logo.** The setup window forbids inline style, so the navy plate and spacing
   come from rules appended to the copied stylesheet, as the other branding there is applied while
   copying, and the build copies `intro.svg` (and the still `mark.svg`) next to the page.
8. **Wordmark typeface without a new dependency.** The in-app wordmark sets its font through the
   brand configuration (`wordmarkFont`) and a stylesheet the UI imports from the brand package, so
   the bundler ships the woff2 with the app (offline on desktop). Mobile has no wordmark text; the
   file is in the package if it needs one. `nurlings-wordmark.svg` embeds the font as base64 so it
   renders the same as an image. Converting the text to outlines (opentype.js) was tried and
   dropped: it pulled in a dependency and rewrote hundreds of lockfile lines.
9. **Animations on the navy plate, as plain images.** The files colour the blob with a CSS variable
   that an `<img>` cannot receive, so the blob is always white; a navy plate makes that read on
   light and dark themes. Their rule for prefers-reduced-motion did not apply inside an `<img>` in
   Chromium with reduced motion emulated (the intro still ran), so the React component checks
   `matchMedia` itself and draws the static mark, and the desktop setup page swaps to a still image
   with a CSS media rule. Mobile cannot show an SVG image, so it keeps the static splash.
10. **Which loading states change.** The web app's opening screen (intro), Reconnecting and
    booting the live desktop (loop). Not changed: the shell skeleton, "Opening your Space", the
    pixel-grid loader and 20-pixel spinners inside cards and buttons, where the mark would be too
    small to read. There is no separate "Nurling is working" indicator apart from the bot avatar's
    working ring, which belongs to the avatar redraw.
11. **Android and splash scale.** The mark is placed so the smallest circle around its visible
    shapes is 672 pixels across (the safe circle is 676), which is larger than fitting its bounding
    box because the box has empty corners. The splash mark spans most of the image and the app shows
    the image 240 points wide (`imageWidth`), where it had been a small part of a default-width
    image.

## Risks / Trade-offs

- The white blob has no contrast on a light page: only dark backgrounds or the plate show it
  fully. → The in-app mark follows the text colour; the transparent PNG source is documented as
  dark-background only.
- Adaptive and notification art are small because of the safe zone and the wide mark. → Reviewed on
  a contact sheet before commit.
- Icon Composer behaviour for an opaque layer is not verifiable here. → Same art as the plain icon;
  a real Xcode build is a manual check in the pull request.

## Migration Plan

Regenerate and commit the files; no data or API changes. Rolling back is reverting the commit.

## Open Questions

None. The bot avatar redraw (Nurlings blob silhouette with two eyes, one colour per bot from a
brand-fitting palette, keeping the working ring and the uploaded-picture override) is a separate
OpenSpec change and pull request after this merges.
